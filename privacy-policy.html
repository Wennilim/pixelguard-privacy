01. Scope & purpose

PixelGuard is a browser extension for inspecting webpage interfaces and verifying their implementation against imported Figma designs. This policy describes data handling in the reviewed extension implementation. Local processing and storage are data handling even when the developer does not receive the data.

No developer backend in this implementation

The extension contains no developer-operated data upload endpoint, analytics integration, advertising SDK, telemetry service, or remote account system. Optional Figma integration and image loading can communicate with third-party services as described below.

02. Data we process

The extension has no dedicated feature for collecting identity profiles, health records, financial information, personal communications, or physical location. However, inspected pages, screenshots, SVG markup, and imported design text may contain personal or sensitive information. Choose inspection targets and designs accordingly.

03. Website content inspection

PixelGuard injects its packaged inspection script into a permitted active tab when you invoke inspection, guides, or a design overlay. It does not declare a content script that automatically runs on every visited website. The inspected content and resulting comparison are processed in the browser and passed between the content script, background worker, and extension interface through internal extension messages.

While picking elements, pointer coordinates and clicks identify the element to inspect. The script also listens for viewport changes and Escape. It does not implement a general typed-text recorder or read the clipboard. Once injected, listeners and a locked selection can remain in the page after picking stops or the side panel closes.

Images, SVGs, video links, and exports

Image previews and exports may load an image or SVG from its source URL. Export requests to a same-origin source can include that website’s credentials or cookies through normal browser request handling; cross-origin export fetches explicitly omit credentials. This does not involve reading cookie values through a cookies API. Ordinary image loading remains subject to browser cookie and referrer rules.

If direct image export is blocked, PixelGuard can capture the entire visible tab as an in-memory screenshot and then crop it to the selected asset. The intermediate screenshot can include other visible content. Exported files are downloaded to your device; copied CSS, animation markup, or other values are written to your clipboard only through the copy controls. Native SVG export preserves source markup and may retain external references or active SVG content.

Displaying a video source link reads its URL. Opening a source link in a new tab makes a normal browser navigation to that resource.

04. Figma API integration

Figma integration is optional. Importing from a Figma URL sends HTTPS GET requests directly to https://api.figma.com/v1 to retrieve a file or selected node and request its PNG preview. These requests include the file key, node identifier where applicable, and your token in the X-Figma-Token header. The token is not placed in the request URL. The implementation does not attach the inspected webpage, a screenshot, or your imported JSON as an API request body.

Figma returns design data and may return a preview image URL hosted by Figma or its image infrastructure. The extension can request that image for its preview and overlay. Preview requests do not add the Figma token header.

Pasted JSON, a JSON file you select, and the included sample are parsed locally without uploading the JSON file. An imported document can nevertheless contain a remote preview URL or CSS image reference that is loaded when displayed. Local JSON parsing does not guarantee a network-free preview.

Overlay visibility to the inspected website

When you enable a design overlay, the preview image is inserted into the inspected webpage’s DOM in an open shadow root. Scripts on that webpage can read the image source, which may be a data URL containing the preview or a remote preview URL. A selected-layer overlay uses visual clipping of the full preview image; this does not hide the remaining image data from page scripts. Enable overlays only on pages you trust with the design preview.

05. Personal Access Token handling

The token input is masked by default and has a visibility toggle. Clicking “Import from Figma” saves the trimmed token before the URL and credentials are validated, including when an import fails. The token is stored under pixelguard.figma.token in the extension origin’s local storage.

The reviewed implementation does not encrypt the token at the application level. It has no session-only storage option, automatic token expiry cleanup, or dedicated “forget token” control. Extension-origin isolation limits ordinary websites’ direct access to this storage; it does not protect the token from someone with access to your browser profile or an extension-context compromise.

The token is used by the Figma client for the two API requests described above. It is not intentionally included in the design overlay, exported files, or developer-server requests. Choose a short-lived token with the minimum Figma scopes you need. PixelGuard does not create, refresh, or revoke tokens.

06. Local data storage

The extension uses the browser’s extension-origin localStorage for these entries:

  • pixelguard.figma.token — the saved Personal Access Token.
  • pixelguard.figma.document — the normalized imported design, including design text, layer metadata, source link, preview URL, and import timestamp.
  • pixelguard.figma.selectedNodeId — the selected design layer.
  • pixelguard.sidepanel.tab — the preferred side-panel tab.
  • pixelguard.locale — the language preference.

Inspection snapshots, comparison results, image conversions, overlay coordinates, and screenshot intermediates are held in memory rather than intentionally saved as an inspection history. The implementation does not use Chrome Storage Sync or upload local storage to a developer account. Browser-, device-, or backup-level handling is outside this extension’s implementation.

07. Third-party services & data transfers

The extension’s network destinations are the Figma API, image hosts referenced by returned or imported previews, webpage image/SVG source hosts used for previews or exports, and destinations you open through source links. Imported documents may specify hosts outside Figma; the current implementation does not enforce a preview-host allowlist or HTTPS-only image URLs.

Request recipients receive the requested resource URL and network connection metadata such as your IP address. Cookies and referrer information depend on the request type, origin, and browser policies. Figma additionally receives the token and design identifiers on its authenticated API requests. These requests are made directly from the browser, without a PixelGuard developer proxy.

Third-party services apply their own privacy practices and may process requests in other countries. Their retention, logging, hosting locations, and deletion practices are not controlled or specified by the extension. See Figma’s privacy policy and the policies of the relevant resource hosts.

No analytics, advertising, crash-reporting, tracking-pixel service, or developer-controlled data recipient is configured in the reviewed extension. A third-party preview URL supplied in imported content can still generate a request to its host.

Privacy policy hosting and contact channel

This policy is hosted on GitHub Pages. GitHub states that it logs and stores visitors’ IP addresses for security purposes, including visits made without signing in. This hosting activity is separate from the extension’s inspection features. The page itself adds no analytics scripts or external fonts. See GitHub Pages data collection and the GitHub Privacy Statement.

If you contact the publisher through the public GitHub Issues link below, the information you choose to post, your GitHub account identity, and any comments or attachments are made available to GitHub, the publisher, and other readers. This is a voluntary external contact channel; the extension does not automatically create issues or send inspection results to it.

08. Retention & deletion

Locally saved preferences, the design document, and the token have no built-in time-based retention limit. They remain until overwritten, removed, or the extension’s storage is cleared.

  1. Clear a design: use “Clear imported design” in the Figma tab. This removes the saved design and selected-node entry and requests removal of the active tab’s overlay. It does not delete the token or preferences. Overlays previously enabled in other tabs may remain until disabled there or those pages are reloaded.
  2. Remove a saved token: open the Figma import form using “Import New” if needed, clear the token field, then click “Import from Figma.” This invokes the existing empty-token removal path and the import will report a missing token or invalid URL. Simply clearing the input without clicking import does not save the change. Advanced users can instead remove the pixelguard.figma.token entry in the extension’s local-storage view in DevTools. Close and reopen extension views afterward to discard their in-memory copy.
  3. Revoke Figma access: revoke the token separately in Figma account settings, under Security. Deleting a locally saved token or uninstalling PixelGuard does not revoke the credential at Figma. See Figma’s token instructions.
  4. Release inspection state: clear the selection or reload/close the inspected page. Closing only the side panel is not a complete deletion action.
  5. Clear persistent extension data: clear the extension origin’s local storage or remove the extension through Chrome’s extension controls. Downloaded assets, clipboard content, browser caches, and backups are separate; manage them using the corresponding device or browser controls.

Deleting local data does not delete the original Figma file or data already handled by third-party servers. PixelGuard implements no server-side user-data store from which the developer can retrieve or erase these local inspection results.

GitHub contact issues and policy-hosting records are separate from local extension data. Clearing extension storage or uninstalling PixelGuard does not remove them. Manage submitted issue content through GitHub’s controls and privacy processes. No automatic issue-deletion or hosting-log deletion mechanism is implemented by this page.

09. Data security

PixelGuard uses Manifest V3, packaged executable code, Chrome’s extension isolation, and user-invoked active-tab access. Its manifest requests sidePanel, activeTab, and scripting; it does not request browsing-history, cookies, or persistent all-sites host permissions. Figma API endpoints are fixed to HTTPS.

These controls have limits: saved tokens and designs have no application-level encryption; preview and resource URLs are not universally restricted to HTTPS; the website can access an enabled overlay’s preview; and exported SVG files can retain source behavior. The implementation does not provide a guarantee of confidentiality against a hostile inspected page, browser-profile access, or compromised device. Avoid using sensitive designs on untrusted websites.

10. Your choices & rights

You can use inspection without importing a Figma design, choose local JSON instead of API authentication, choose which elements to inspect, disable overlays, clear local designs and tokens, revoke Figma tokens, or uninstall the extension. Export and clipboard actions are optional user controls.

Depending on applicable law, you may have rights concerning access, correction, deletion, restriction, objection, or portability of personal information. The local controls above address data held by the extension. For information held by Figma or other resource hosts, contact those providers. Privacy requests to the publisher can use the GitHub Issues contact below; no automated privacy-request service is implemented.

11. Chrome Web Store Limited Use

PixelGuard limits the use of data accessed through Chrome APIs and its inspection and Figma features to its disclosed purpose: webpage UI inspection, asset export, and design verification. Its implemented transfers support those features. It does not sell user data, use or transfer it for advertising or unrelated profiling, or use or transfer it for creditworthiness or lending decisions. This use restriction follows the Chrome Web Store User Data Policy’s Limited Use requirements.

The reviewed extension does not send inspection data to the developer or provide a developer interface for remotely reading it. This statement about data use does not remove the storage and overlay security limitations described in this policy.
